再生すると、索引をたどる順番が見られます。

索引なしは表を最後まで。索引ありは場所を絞って該当行へ。

補足｜探索を止める条件
  • 索引なし： 同じ顧客の注文は表の離れた場所にもあるので、条件に合う注文をすべて返すには最後まで見ます。
  • 索引あり： 枝を下って最初の4242へ。索引で4243に変わったら探索を終え、4242の項目が指す注文行に進みます。

❓ 疑問

検索が速くなるなら、すべての列にインデックスを作るとよい？

⌨️ 操作

②の2件と③の4万9千件で、DBが選ぶ探し方を比べてみましょう。

① 索引なし・2件
② 索引あり・2件
③ 索引あり・多くの行
実行するSQLを表示（PostgreSQL）
BEGIN;  -- 練習を始める
CREATE TEMP TABLE index_lesson_orders AS  -- 練習用の注文表を作る
SELECT n AS order_no,
       CASE WHEN n IN (308, 18000) THEN 4242  -- 注文 #308 と #18000 の顧客IDを4242にする
            WHEN n = 4242 THEN 308  -- 注文 #4242 は別の顧客にして、該当を2件にする
            ELSE n END AS customer_id
FROM generate_series(1, 50000) AS n;  -- 注文番号を1から50000まで用意
ANALYZE index_lesson_orders;  -- DBが見積もりに使う統計を更新

-- ① 索引なし
EXPLAIN (COSTS OFF)  -- DBが選ぶ探し方を表示
SELECT * FROM index_lesson_orders WHERE customer_id = 4242;

-- ② 索引あり
CREATE INDEX ON index_lesson_orders (customer_id);  -- 顧客IDで探せる索引を作る
ANALYZE index_lesson_orders;
EXPLAIN (COSTS OFF)
SELECT * FROM index_lesson_orders WHERE customer_id = 4242;

-- ③ 多くの行が該当する場合
EXPLAIN (COSTS OFF)
SELECT * FROM index_lesson_orders WHERE customer_id <= 49000;  -- 条件に当てはまる4万9千件を探す
ROLLBACK;  -- 練習で作った表と索引を取り消す

📋 結果を見てみよう（表示例）

表示例
① Seq Scan on index_lesson_orders
     Filter: (customer_id = 4242)

② Index Scan using index_lesson_orders_customer_id_idx on index_lesson_orders
     Index Cond: (customer_id = 4242)

③ Seq Scan on index_lesson_orders
     Filter: (customer_id <= 49000)

Seq Scan は表を順に読み、Index Scan は索引を使います。表示はデータの分布やDBの設定で変わります。

✅ 答え

よく使う検索で少数の行に絞れる列から、索引を検討します。

まとめ

実データに近い環境で、実行計画・検索と更新の時間・索引の容量を比べます。実測時間を見るには EXPLAIN ANALYZE を使います。
