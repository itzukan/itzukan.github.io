はじめてのGit

Gitは、ファイルの変更を履歴に残す道具です。変更を別々に記録しておくと、うまくいった修正を残して、問題のあった修正だけを取り消せます。

ファイルの保存とコミットはどう違う？

お店の案内文を10時開店から9時開店に直してみましょう。保存はファイルを書き替える操作です。コミットは、保存した内容をGitの履歴に記録する操作です。

作業中のファイル

shop.txt ✓ 保存済み

開店時刻：10:00

昨日の案内文はコミット済みです。まず①を押して、今日の案内文を9時開店に変えましょう。

Gitで変更をコミットする

    
さっき保存した shop.txt の「9時開店」を、コマンドでコミットする例です。コマンドはGitで管理しているフォルダー（リポジトリ）で実行します。

    
    

      補足（ステージに入れる・外す）
      
      
git diff でステージに入っていない変更、git diff --staged で入っている変更を確認できます。

      
git add で入るのは、その時点の内容です。あとから追記した分もコミットするなら、もう一度 git add します。

    

  


  

    
ブランチとマージ

    
ブランチは、別々に変更をコミットできる履歴の枝です。公開用の main から作業ブランチを作り、開店時刻を9時に変更します。確認が済んだら main に取り込みます。この取り込みをマージと呼びます。

    
    
図の feature は feature/opening-hours の略です。

    
    
      
  1. git switch -c feature/opening-hours で作業ブランチを作って移動します。git status で今いるブランチを確認できます。
    2. 
      
  2. 案内文を修正し、git add shop.txt と git commit -m "開店時刻を9時に変更する" で作業ブランチにコミットします。
    3. 
      
  3. 確認が済んだら git switch main で取り込み先に移動し、git merge feature/opening-hours で取り込みます。main に別の変更がなければ、作業ブランチと同じコミットまで進みます。
    4. 
    

  


  

    
競合（コンフリクト）を解消する

    
同じ行を別々に修正すると、Gitがどちらを残すか決められず、マージが止まることがあります。これが競合です。依頼や仕様を確認し、採用する修正を残してからマージを続けます。

    
    
    
競合の解消手順

    
    
      
  1. 何を残すか決める。 この例の依頼は「開始を9時に、終了を20時にする」です。main の開始時刻と、取り込み側の終了時刻を残します。判断に迷ったら、依頼者に正しい内容を確認します。
    2. 
      
  2. 採用する内容に置き換えて保存する。 shop.txt を開き、<<<<<<< から >>>>>>> までを、印や採用しない行も含めて 営業時間：09:00〜20:00 の1行に置き換えます。
    3. 
      
  3. Gitに解消したことを伝える。 git add shop.txt で修正した内容をステージに入れ、git commit -m "営業時間を9時から20時に統一する" でマージを完了します。
    4. 
    

  


  

    
コミットした変更を取り消す（git revert）

    
    
git log --oneline で調べたいコミットIDを探します。git show の後ろに、見つけたコミットIDを入れると、変更前と変更後を確認できます。

    
原因が分かったら git revert --no-edit b26ef13 を実行します。競合がなければ、git revert が予約枠を20組に戻すコミットを自動で追加します。店舗写真と元のコミットは残ります。

  


  

    
GitとGitHubの違い

    
Gitは変更を履歴に残す道具です。GitHubは、Gitで管理するプロジェクトをオンラインで共有し、チームで確認できるサービスです。

    
  


  

    
リモートと変更をやり取りする

    
リモートから変更を受け取る（fetch・pull）

    
    
    
      
  • 内容を確認するだけなら git fetch origin で取得し、git log --oneline HEAD..origin/main でリモートにだけあるコミット、git show コミットID で差分を確認します。HEAD は今見ているコミットです。
    • 
      
  • 変更を取り込むときは、ローカルの main で git status を確認します。リモートだけが先に進んでいれば、git pull でローカルも同じ地点まで進められます。この例ではローカルの main が origin/main を追跡する設定になっています。
    • 
    

    

      補足（ローカルとリモートの両方に変更があるとき）
      
      
git log --oneline origin/main..HEAD で、ローカルにだけあるコミットを確認できます。

    

    
リモートに作業ブランチを送る（push）

    
    
送る前に git status と git log --oneline でブランチとコミットを確認します。図の git push -u でリモートに同名の作業ブランチを作り、ローカルの作業ブランチと対応づけます。

  


  

    
プルリクエストの差分を見る

    
プルリクエスト（PR）は、変更を取り込む前にチームに確認を頼む仕組みです。

    
    
作業ブランチで git diff main...HEAD を実行すると、main との共通地点から作業ブランチで追加した変更を見られます。

    
いまの依頼と関係のない変更が混じっていたら、ファイル名と修正してほしい内容を伝えます。
