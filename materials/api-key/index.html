はじめてのAPIキー

APIキーは、APIを呼び出すときに使う認証情報の一つです。APIキーを付けると、同じリクエストへの応答がどう変わるか試してみよう。

APIキーを付けて商品一覧を取得する

リクエストはブラウザー内で模擬実行されます。

  1. 入力欄を空のまま「リクエストを送信」を押し、401 を確認します。
  2. 「練習用APIキーを入れる」を押してもう一度送り、200 と商品一覧を確認します。

GET /products

演習では誰でも使える練習用APIキーを使います。実際のサービスから発行されたAPIキーはここに入力しないでください。

リクエストの見本

GET /products

実際のサイトではどう使う？

    
たとえば、コーヒー器具の紹介サイトで、楽天市場のコーヒーミルを写真と価格つきで並べたいとします。サイトのサーバーが楽天市場の商品検索APIに問い合わせます。

    
紹介サイトで「コーヒーミル」を検索すると

    
    
      
  1. 
        
        利用者のブラウザー
        検索欄に「コーヒーミル」と入力して検索。
      
    2. 
      
  2. 
        
        紹介サイトのサーバー
        検索語とAPIキーを楽天市場に送る。
      
    3. 
      
  3. 
        
        楽天市場の商品検索API
        APIキーを確認し、検索に合う商品の名前・価格・画像URLを返す。
      
    4. 
    

    
↩ 紹介サイトの画面にコーヒーミルの写真・商品名・価格が並ぶ。

    

      
APIキーの置き場所

      
開発者が、楽天市場から発行されたAPIキーを紹介サイトのサーバーのシークレット設定に登録します。

      
APIキーは秘密にしておきます。ブラウザーに配信するJavaScriptに書くと、ページを開いた人が読み取れます。

補足　curlで自分のPCから呼び出す

    

      Windows・Macの手順を開く
      
Python 3が使えるPCで試せます。練習用サーバー（practice-server.py）をダウンロードし、保存したフォルダーでターミナルを開きます。

      
サーバーを起動する

      
Windows（PowerShell）

      
py -3 practice-server.py

      
Mac（ターミナル）

      
python3 practice-server.py

      
別のターミナルから、APIキーを付けずに送信し、次に付けて送信する

      
Windows（PowerShell）

      
curl.exe -i http://127.0.0.1:8711/products
curl.exe -i -H "Authorization: Bearer itzukan-demo-key" http://127.0.0.1:8711/products

      
Mac（ターミナル）

      
curl -i http://127.0.0.1:8711/products
curl -i -H "Authorization: Bearer itzukan-demo-key" http://127.0.0.1:8711/products

      
127.0.0.1 は自分のPCです。応答の先頭行が HTTP/1.0 401 Unauthorized から HTTP/1.0 200 OK に変わることを確認したら、サーバー側の画面で Ctrl＋C を押して終了します。
