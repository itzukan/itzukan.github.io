ファイアウォールとは？

ファイアウォールが、通信をルールで許可したり拒否したりする様子を見てみましょう。

図で仕組みを理解しよう

💻 PCからWebを開くHTTPS / TCP 443
→
🛡️ ルール確認✅ 許可ルールに一致
→
🌐 Webサーバー通信が届く
💻 同じPCから管理するSSH / TCP 22
→
🛡️ ルール確認🛑 一致する許可ルールがない
✕
🖥️ 管理サービス通信が届かない

同じPCから同じサーバーへの通信でも、ポート番号で結果が変わる架空の例です。

セキュリティグループの設定例

対象　Webサーバー（架空）

インバウンドルール（サーバーに入る通信）
タイププロトコルポート送信元（接続する側）
HTTPSTCP443203.0.113.10/32

/32 は、ここでは図のPCのIPアドレス1つだけを指定しています。

  • ✅ TCP 443 は通る同じ送信元・プロトコル・ポートの許可ルールがある。
  • 🛑 TCP 22 は通らない送信元が同じでも、TCP 22 の許可ルールがない。

AWSのセキュリティグループに登録するのは許可ルールです。この例では、表に一致する通信だけを通します。 AWS公式のルール仕様

❓ 疑問

ネットにつながっていても、一部のサービスだけ使えないのはなぜ？

💡 理由

ファイアウォールは、通信の向き、送信元・宛先IP、TCPかUDPか、宛先ポート番号などをルールと照合します。何を許可するかはネットワークの用途に合わせて決めるので、ネットワークが変わると同じ通信の扱いも変わる場合があります。

⌨️ 操作

Windows　Windows PowerShellで、TCP 443の接続が成立するか、公開教材を相手に1回確認します。

Windows PowerShell
Test-NetConnection free.itzukan.com -Port 443 | Select-Object ComputerName,RemotePort,TcpTestSucceeded

Mac　Macのターミナルから同じ公開教材のTCP 443を1回確認します。

Mac ターミナル
nc -vz -G 5 free.itzukan.com 443

📋 結果を見てみよう（表示例）

Windows PowerShell
ComputerName      RemotePort TcpTestSucceeded
------------      ---------- ----------------
free.itzukan.com         443             True

TcpTestSucceeded の True は、TCP接続が成立したという意味です。

Mac ターミナル
Connection to free.itzukan.com port 443 [tcp/https] succeeded!

succeeded! は、TCP接続が成立したという意味です。

✅ 答え

ネットに接続できても、目的の通信がファイアウォールで拒否されれば宛先に届きません。

まとめ

接続に失敗する原因には相手が待ち受けていない、経路に問題がある場合もあります。接続結果と管理者が確認するルール・ログを照合します。
