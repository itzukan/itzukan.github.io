ネットワーク入門

CDNとは？設定ミスで他人のページが見える理由

商品画像はみんなで再利用できますが、マイページは利用者ごとに内容が違います。

図で仕組みを理解しよう

🖼️ 商品画像誰が見ても同じ
→
📦 近くのCDNコピーを共有キャッシュに保存
→
👥 複数の利用者近い場所から同じ画像を受け取る
👤 個人用ページ利用者ごとに内容が違う
→
🛑 CDNの設定ミス共有キャッシュに保存してしまう
→
⚠️ 別の利用者の画面他人用の内容が表示される場合がある

キャッシュは再利用のためのコピー。共有キャッシュは複数の利用者が共用します。図は架空の事例です。

❓ 疑問

同じURLを開く人どうしで、別の人のマイページが見えてしまうのはなぜ？

💡 理由

CDNは利用者に近い配信サーバーからキャッシュを返し、ファイルを速く届けます。個人用の応答を誤って共有キャッシュに保存・再利用すると、別の利用者に返ることがあります。この例の原因は、フレームワークの名前では判断できません。サーバーが返すキャッシュ指定と、CDN側で個人用の応答を共有しないルールの両方を確認します。

⌨️ 操作

Windows　PowerShellで、自分のアカウント情報を含まない公開教材の応答ヘッダーを確認します。

Windows PowerShell
curl.exe -I https://free.itzukan.com/materials/

Mac　ターミナルで、同じ公開教材の応答ヘッダーを確認します。

Mac ターミナル
curl -I https://free.itzukan.com/materials/

📋 結果を見てみよう（表示例）

Windows PowerShell
HTTP/1.1 200 OK
Cache-Control: max-age=600

公開ページの表示例です。max-age=600 は、応答が新鮮と見なされる時間が600秒という指定です。

Mac ターミナル
HTTP/2 200
cache-control: max-age=600

公開ページの表示例です。大文字・小文字、他のヘッダー、設定値は実行時で変わります。

✅ 答え

利用者ごとの応答を共有キャッシュに保存させないようにします。Cache-Control: private は共有キャッシュに保存しない指定、no-store はブラウザーなどのキャッシュにも保存しない指定です。

まとめ

表示されたヘッダーだけで、実際にCDNが保存したかどうかは判断できません。サービス管理者は個人用ページを共有キャッシュの対象から外し、設定と応答を確認します。

参考資料 RFC 9111のCache-Controlの定義
