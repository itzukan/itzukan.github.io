はじめに

この教材は、こんな人のための入門書です。

💻 PC→ Wi-Fi →📡 ルーター→ HTTPS →🌐 Webサイト

👥 対象者

ネットワーク初心者、基本情報技術者試験の学習者、これからエンジニアを目指す人。

🎯 読み終えたらできること

ネットワークの基本的な通信の流れを説明し、自分のPCでIPアドレス・DNS・通信経路を確認し、結果を読み取れる。

🧰 必要なもの

自宅のWi-FiにつながったWindows 11またはMac。インターネット接続。プログラミング経験・有料サービスは不要。

第1章 Wi-Fiとインターネット

Wi-Fiにつながることと、インターネットを使えることは別です。

💻 自分のPC→📶 Wi-Fi接続→📡 ルーター→🌐 インターネット
💻 PC→ Wi-Fi →📡 ルーター→ HTTPS →🌐 Webサイト

❓ 疑問

Wi-Fiにつながったのに、サイトが開かないのはなぜ？

💡 理由

Wi-Fiとインターネットは別。まず接続先を知ろう。

⌨️ 操作

Windows：スタート → 設定 → ネットワークとインターネット → Wi-Fi。接続中のSSIDを確認。

Mac：Appleメニュー → システム設定 → Wi-Fi。接続中のSSIDを確認。

📋 結果

Wi-Fi：オン　接続先：Home_WiFi　状態：接続済み（模式例）。SSIDはネットワーク名で家ごとに異なります。

✅ 答え

Wi-Fi接続は家の機器まで。ネット接続は別途必要。

第2章 IPアドレス

PCが家庭内ネットワークで使う「住所」を見つけます。

💻 PC 192.168.1.20→↔ 家庭内LAN→📡 ルーター 192.168.1.1

❓ 疑問

同じ家のPCやスマホは、どうやって区別される？

💡 理由

家庭内の通信先を識別するIPアドレスを知ろう。

⌨️ 操作

Windows：ターミナル（PowerShell）で ipconfig を実行しWi-Fi欄のIPv4アドレスを確認。

Mac：システム設定 → Wi-Fi → 接続中の「詳細」 → TCP/IPでIPアドレスを確認。

📋 結果

Windows例：IPv4 Address : 192.168.1.20 / Default Gateway : 192.168.1.1。

Mac例：IPv4の構成 DHCP / IPアドレス 192.168.1.20 / ルーター 192.168.1.1。値は環境により異なります。

✅ 答え

家庭内では各端末のIPアドレスで通信先を区別。

第3章 ルーターとゲートウェイ

PCがインターネットへ通信するときの「最初の送り先」を知ろう。

💻 PC→➡ 基本の送り先→📡 Wi-Fiルーター→➡ 外へ転送→🌐 Web

❓ 疑問

PCは外のWebサイトへ、まずどこにデータを送る？

💡 理由

最初の送り先がわかると、通信の流れを追いやすくなる。

📘 理解する

ルーターはネットワーク間でデータを転送する機器。デフォルトゲートウェイはPCが基本の送り先として使う相手。家庭では通常Wi-Fiルーターが担当。

⌨️ 操作

Windows：ipconfig を実行しDefault Gatewayを確認。

Mac：route -n get default を実行しgateway: の値を確認。

📋 結果

PC 192.168.1.20 → ルーター 192.168.1.1 → Webサイト（説明用の値）。

✅ 答え

通常、PCは外部宛ての通信をルーターへ送ります。

第4章 DNSのしくみ

ドメイン名に対応するIPアドレスを調べる仕組みです。

💻 google.com→❓ DNSに問い合わせ→🗂️ DNSサーバー→↩ IPアドレス

❓ 疑問

google.com というドメイン名で、なぜサイトを開ける？

💡 理由

DNSでドメイン名に対応するIPを調べてみよう。

⌨️ 操作

Windows：nslookup -type=A google.com

Mac：nslookup google.com

📋 結果

Server: home-router / Address: 192.168.1.1 / Name: google.com / Address: 142.250.196.14（説明用の例）。

✅ 答え

DNSがドメイン名に対応するIPを返す。値は変わる。

第5章 HTTPSの役割

Webサイトとの通信をTLSで保護する仕組みを体験します。

💻 PC→🔒 HTTPS / TLS→🌐 Webサイト

❓ 疑問

HTTPSで接続できたか、PCで確かめられる？

💡 理由

コマンドでHTTPSの応答を確認してみよう。

⌨️ 操作

Windows：curl.exe -I -4 https://www.google.com

Mac：curl -I https://www.google.com

📋 結果

HTTP/2 200 / content-type: text/html; charset=UTF-8（表示例）。HTTP/1.1や別の状態コードの場合もあります。

✅ 答え

HTTP応答が表示され、HTTPSで接続できた。通常curlは証明書を検証しますが、詳細や暗号化内容の表示ではありません。HTTPSはサイト自体の安全性を保証しません。

第6章 pingとICMP

pingで「応答が届くか」と「往復時間」を確かめよう。

💻 PC→➡ Echo Request→🌐 通信先→↩ Echo Reply

❓ 疑問

通信先から返事は届く？

💡 理由

pingの結果から応答数と往復時間を読み取るため。

📘 理解する

ICMPは通信状況やエラーを知らせるプロトコル。pingはEcho RequestとEcho Replyを使います。

⌨️ 操作

Windows：ping -4 -n 4 google.com

Mac：ping -c 4 google.com

📋 結果

Windows例：Reply from 142.250.196.14: time=12ms / Sent = 4, Received = 4, Lost = 0。

Mac例：64 bytes from 142.250.196.14: time=12.0 ms / 4 packets transmitted, 4 received, 0.0% packet loss。

✅ 答え

4回送って4回返事が届いた例。timeは往復時間。ICMPを拒否する通信先では失敗することもあり、ping失敗だけでWebサイトが使えないとは判断できません。

第7章 通信経路を見てみる

途中の機器と、目的地までの到達を調べよう。

💻 自分のPC→① 192.168.1.1→②〜⑤ * 応答なし→⑥ 目的地に到達

❓ 疑問

途中が「*」なのに、Googleまで届くの？

💡 理由

途中の機器が調査に応答しなくても通信を転送できるため。

📘 理解する

ホップは目的地へ向かう途中でルーターなどを通る段階。「*」は応答が見えない印で、通信がそこで止まったとは限りません。

⌨️ 操作

Windows：tracert -4 -h 20 google.com

Mac：traceroute -I -m 20 google.com

📋 結果

1ホップ目：192.168.1.1 / 2〜5ホップ目：* * * / 6ホップ目：192.178.230.113（PDF掲載の説明用サンプル・実測例）。

✅ 答え

最後に目的地のIPが表示されれば到達を確認できた。途中が「*」でも故障とは限らず、HTTPSが使えるかは別途確認します。

第8章 つながらないときの確認順

近いところから調べると、原因の範囲を絞れます。

🔎 確認する

① Wi-Fi：接続中のSSIDは自宅のもの？

🔎 確認する

② IPアドレス：Wi-FiにIPv4アドレスが付いている？

🔎 確認する

③ ゲートウェイ：外へ出るための送り先が設定されている？

🔎 確認する

④ DNS：nslookup google.com にIPの回答がある？

🔎 確認する

⑤ HTTPS：正しいURLで開ける？ 警告はない？

✅ 答え

ping・経路表示は補助的な確認。失敗だけで断定しない。

まとめ Webサイトが表示されるまで

今日の操作を、ひとつの通信の流れにつなげよう。

💻 PC→📡 ルーター→🗂️ DNS→🔒 HTTPS→🌐 Webサイト

📘 理解する

① PCがWi-Fiで家庭内ネットワークにつながる。② DNSがサイト名に対応するIPアドレスを返す。③ ルーター等を経由してWebサイトへ接続する。④ HTTPS（TLS）でWebの通信内容を保護する。

🔎 確認する

□ 自宅のSSIDを確認した。□ PCのIPアドレスとゲートウェイを見つけた。□ nslookupの回答IPを確認した。□ HTTPSの警告とURLを確認した。□ pingと経路表示の意味がわかった。

異常な結果を比較し、原因を切り分ける実践編へ。
