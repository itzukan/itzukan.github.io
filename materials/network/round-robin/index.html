ラウンドロビンとは？順番に振り分ける仕組み

Webへのアクセスを3台のサーバーへ順番に配る方法を、ラウンドロビンと呼びます。

図で仕組みを理解しよう

① 1件目🖥️ サーバーA
→
② 2件目🖥️ サーバーB
→
③ 3件目🖥️ サーバーC
→
④ 4件目🔁 またサーバーA

この図では、ロードバランサー（アクセスを複数のサーバーに配る仕組み）が、1件ずつ順に振り分けています。

❓ 疑問

3台に同じ件数を振り分ければ、それぞれの負荷も同じになる？

💡 理由

画像を1枚返す処理と大きな集計では、1件にかかる時間が違います。ラウンドロビンがそろえるのは割り当て順で、負荷は処理内容にも左右されます。故障したサーバーを候補から外すには、応答を調べるヘルスチェックと、その結果を振り分けに反映する仕組みが必要です。

⌨️ ミニ演習｜アクセスを振り分ける

黄色い点は1件のアクセスです。ボタンを押して、ロードバランサーからどのサーバーに届くか見てみましょう。

🔀 ロードバランサー
🖥️ サーバーA
🖥️ サーバーB
🖥️ サーバーC

まだアクセスは送っていません。

届いた順番 —

ブラウザー上のシミュレーションです。実際のサーバーには通信しません。

🔄 DNSでも「順番を回す」ことがある

上の図では、ロードバランサーがアクセス1件ごとに転送先を選びます。DNSラウンドロビンでは、同じサイト名に複数のIPアドレスを登録し、DNSが返す候補の順番を入れ替えます。

1回目の回答例🖥️ A → B → C先頭から試すアプリなら、まずAに接続を試す
2回目の回答例🖥️ B → C → A先頭から試すアプリなら、まずBに接続を試す

最初に試される候補が変われば、接続先が分散することがあります。実際にどのIPアドレスを使うかは、OSやブラウザーなど、接続する側の動作によります。

補足｜nslookupでDNSの候補を見る

WindowsのPowerShell、またはMacのターミナルで、同じコマンドを3回実行します。-type=A はIPv4アドレスを尋ねる指定です。Webページを開く代わりに、DNSへ接続先の候補を尋ねます。

実行するコマンド
nslookup -type=A free.itzukan.com

📋 結果を見てみよう（回答欄の表示例）

1回目
185.199.109.153
185.199.110.153
185.199.111.153
185.199.108.153
2回目
185.199.110.153
185.199.111.153
185.199.108.153
185.199.109.153

なぜ先頭を見る？ DNSの回答を先頭から試すアプリなら、上の例では1回目は 185.199.109.153、2回目は 185.199.110.153 にまず接続を試します。

これがラウンドロビンとのつながりです。 DNSが回答の先頭を順番に入れ替えると、最初に試されるIPが変わり、接続先が分散することがあります。nslookup は候補を聞くだけなので、実際にどのIPへ接続したかは分かりません。

free.itzukan.com は候補の一覧を観察するための例です。順番が変わる理由にはDNSサーバー側の並べ替えなどもあり、この結果だけでサイトの構成は断定できません。DNSが前の回答を一時保存している場合などは、同じ順番で返ることもあります。

✅ 答え

各サーバーに同じ件数を配っても、1件ごとの処理の重さが違えば負荷は変わります。

まとめ

ラウンドロビンは、A → B → C → A のように順番に振り分け、一周したら最初に戻る仕組みです。

  • ロードバランサーのラウンドロビンでは、届いたアクセスの転送先を順番に切り替えます。
  • DNSラウンドロビンでは、接続先の候補の順番を入れ替えます。アプリが先頭のIPアドレスから試す場合は、接続先が分散することがあります。nslookup で確認できるのは候補の順番までです。

同じ件数を配っても、処理の重さが違えば負荷に差が出ます。故障したサーバーを候補から外すには、ヘルスチェックの結果を振り分けに反映する仕組みが必要です。
